# kotatsuredo-server

Community server for [Kotatsu-Redo](https://github.com/Kotatsu-Redo/Kotatsu-Redo): comments, ratings,
and the telemetry that drives source scoring in search, alternatives and the source list.

The full design lives in **[PLAN.md](PLAN.md)** — read that before changing anything structural.

## Status

**Ready to host.** Identity, telemetry, source scoring, work resolution, ratings, comments, the word
filter and the moderation panel are built on the server; the rating row, comment sheet and reply
notifications are built in the app. **To stand an instance up, follow
[DEPLOY.md](DEPLOY.md).**

The word filter ships with curated lists for all fifteen launch languages — 3,018 terms, generated by
[`tools/curate_wordlists.py`](tools/curate_wordlists.py), which records every judgement that produced
them, and measured at a **0.00% false-positive rate in 14 of 15 languages** (English 0.95%) against
ordinary prose by [`FilterAuditTest`](src/test/kotlin/io/kotatsuredo/server/FilterAuditTest.kt). See
[the seed README](src/main/resources/filter/seed/README.md) for what that audit found and what is
left.

**Chapter alignment (M2c)** is still outstanding, and comes after the first comment release on
purpose: work-level threads are useful
alone, and alignment is the piece most likely to need a second pass once real cross-source data
exists. Until it lands, chapter threads are keyed by the chapter number scaled by 100.

## Policies

[`legal/`](legal/) holds the [terms](legal/TERMS.md), [content policy](legal/CONTENT-POLICY.md) and
[privacy notice](legal/PRIVACY.md) for the official instance. They are Markdown in the repository so
every change is a reviewable diff, and the server renders them at `/terms`, `/content-policy` and
`/privacy` so what a user opens is the text that was committed.

`PolicyClaimsTest` asserts the privacy notice's specific promises against the live schema — no column
anywhere could hold an IP address, telemetry is deleted at seven days, deleting an account cannot
cascade into other people's comments. A migration that breaks one fails the build.

## Running locally

```sh
cp .env.example .env      # then edit the passwords
docker compose up --build
curl http://localhost/v1/health
```

Without Docker, against a Postgres you supply:

```sh
export DATABASE_URL=jdbc:postgresql://localhost:5432/kotatsuredo
export DATABASE_USER=kotatsuredo DATABASE_PASSWORD=...
./gradlew run
```

### Tests

Unit tests need nothing. The integration tests need a real Postgres and take one from the
environment — they skip loudly when it is absent, so a machine without a database still builds.

```sh
docker compose -f docker-compose.yml -f docker-compose.test.yml up -d postgres

export TEST_DATABASE_URL=jdbc:postgresql://localhost:5432/kotatsuredo
export TEST_DATABASE_USER=kotatsuredo TEST_DATABASE_PASSWORD=...
./gradlew test
```

CI supplies the same via a service container, and fails the build if the integration tests were
skipped — otherwise a broken CI database would quietly produce a green build.

## Endpoints

Every endpoint below `/v1/identity` requires `Authorization: Bearer <secret>`. There is no anonymous
access path: a user who does not want an identity turns the feature off in the app and never calls.

| | |
|---|---|
| `GET /v1/health` | `200` healthy, `503` when the database is unreachable. What uptime monitoring should watch. |
| `GET /v1/version` | Server and API version. |
| `POST /v1/identity/hello` | Create-or-touch. First call from an unknown secret creates the account. Carries the device identifiers. |
| `GET /v1/identity/me` | The caller's identity and trust tier. |
| `POST /v1/identity/nickname` | Set or change the nickname. |
| `DELETE /v1/identity/me` | Delete everything about this user. |
| `POST /v1/telemetry/probes` | Batched, fire-and-forget source probes. `202`. |
| `GET /v1/sources/scores?region=` | All source scores for a region. ETag + `max-age=3600`; the app polls daily and usually gets `304`. |
| `POST /v1/works/resolve` | Batch: source fingerprints → work ids. The hot path. |
| `POST /v1/works/link` | A user migration confirming two source entries are the same work. |
| `POST /v1/works/{id}/dispute` | "This work is wrong." Files a queue item; duplicates collapse. `202`. |
| `GET /v1/works/{id}/rating` | Aggregate plus this caller's own value. |
| `PUT`/`DELETE /v1/works/{id}/rating` | Set or clear it. Half-star steps, `1..10`. |
| `GET /v1/works/{id}/comments` | A page of root comments with their replies. `?sort=top\|new&lang=&chapter=&limit=&offset=` |
| `POST /v1/works/{id}/comments` | Post or reply. Published instantly. |
| `PATCH`/`DELETE /v1/comments/{id}` | Edit inside five minutes; delete leaves a tombstone. |
| `PUT /v1/comments/{id}/vote` | `{value: 1 \| -1 \| 0}`. Idempotent, so a retry cannot double-count. |
| `GET /v1/notifications?since=` | Replies to my comments. Delivered once; the cursor lives on the device. |
| `POST /v1/filter/blocks/{id}/dispute` | "This was wrong", from the rejection dialog. Once, and only your own. |
| `GET /rules` | The community rules the rejection dialog links to. Served by the instance, not GitHub. |

### The moderation panel

`/admin` — a static page served by the same container, with its API under `/admin/api`. Separate
from `/v1` on purpose: a different audience, a different auth model, and nothing an app client holds
can reach it.

Set `MOD_BOOTSTRAP_USERNAME` and `MOD_BOOTSTRAP_PASSWORD` once to create the first admin. That path
disables itself the moment any moderator exists. The account must enrol an authenticator before it
can do anything — until it has, every endpoint but the two enrolment ones refuses it.

Roles are `moderator` (comments and users) and `admin` (also moderators, work merges, device-ban
reversal, and the full audit log). Every action writes to `mod_action`, which the database itself
refuses to update or delete.

### The word filter

Every comment and nickname passes it synchronously in the POST handler. Pass and it publishes at
once; fail and it is rejected naming the offending term. Three tiers: `severe` (global, substring,
set B), `profanity` (the comment's language plus English, whole-token, set A) and `watch` (publishes
and flags).

Almost all of the work is done by one rule — **block only if the match is the whole token, or the
containing token is not itself a known word** — which is what makes `assassin`, `Scunthorpe` and
`therapist` postable without any context model.

The lists live in `filter_rule`, not in the jar: they are configuration to be tuned from the panel.
Every block is logged, users can report a false positive in one tap from the rejection dialog, and a
rule whose confirmed false-positive rate crosses 30% demotes itself.

## Things that are load-bearing

A few decisions here look like ordinary config and are not. Each has a comment at its site saying so;
this is the index.

- **`deploy/Caddyfile` disables access logging.** The privacy notice says IP addresses are never
  stored. That is true only while that block exists.
- **`plugins/Plugins.kt` builds its log line from an allow-list of four fields.** The bearer secret is
  the identity, so a logged `Authorization` header hands out accounts. `LoggingRedactionTest` fails the
  build if this regresses.
- **Migrations run at startup and abort the process on failure.** A server on an unexpected schema is
  worse than a server that is plainly down.
- **Errors are codes, never prose.** The app localizes; the server never holds translations.
- **`is_shadowbanned` never crosses the wire.** A shadowban works only while nothing signals it
  happened, so it is absent from every response — including the user's own `identity/me`.
- **Only `ssaid_hash` is ever auto-banned.** The MediaDrm hash raises a flag for a human because DRM
  ids collide across devices; banning on one would hit a stranger who did nothing.
- **`DEVICE_PEPPER` has no default and changing it invalidates every existing device ban.**
- **The telemetry reporter id is `HMAC(user secret, day)`.** Keyed by the secret — which the server
  never stores — so nobody can map a pseudonym back to a user after the request ends, not even with
  the whole database and every server-side key. A pepper-over-user_id would look similar and be
  retroactively reversible for everyone at once.
- **`TelemetryRetention` is a promise, not a cron job.** "Raw probe rows are deleted within 7 days"
  is a sentence in the privacy notice; if that loop stops, the sentence stops being true.
- **Stability uses a Wilson lower bound, never a raw success ratio.** A source with one lucky success
  would otherwise outrank one with four thousand. `ScoringTest` asserts this directly.
- **`sample_size` and `median_composite` exist to stop new sources starving.** An unproven source must
  not score near zero, or it is never queried, so it never earns data, so it is never queried. The
  client scores anything under-sampled at the median instead.
- **Popularity counts distinct reporter-days, not events**, so one enthusiastic user cannot define
  what is popular.
- **Resolving never merges two existing works.** It assigns an alias or creates a work. Merging
  happens only via `works/link`, where a guard refuses when both sides already carry user content —
  an unmerged pair is an annoyance, a wrong merge mixes two communities irreversibly.
- **Trigram candidate generation is loose (0.40), acceptance is strict.** Measured: two renderings of
  the same work score 0.48, so a tight net never surfaces the candidate and the cover hash never gets
  to decide. Title-alone acceptance needs 0.85.
- **Cover hashes are only ever compared against candidates the title already produced**, never
  searched globally — which is why no hash index exists.
- **A merge never destroys the losing work.** It becomes a redirect: lookups ignore it, clients
  holding its id get `work_moved`, and `comment.origin_work_id` / `rating.origin_work_id` carry
  content home if the merge is undone. `countWorks()` does not count redirects.
- **Removing a comment blanks its text and keeps the only copy in `mod_action.detail`.** That is what
  makes the audit log answer "what did it say", and it is the sole path a restore can read from — so
  a comment its own author deleted has no snapshot and cannot be restored by a moderator.
- **`mod_action` is append-only in the database**, not by convention. A trigger raises on `UPDATE` and
  `DELETE`; `ModerationServiceTest` asserts both.
- **TOTP steps are burned on use.** A code is valid for thirty seconds, which is long enough to be
  read over a shoulder and replayed. `Totp` is checked against all five RFC 6238 test vectors,
  because a hand-rolled implementation that only agrees with itself is a guess.
- **The panel's session is an httpOnly, `SameSite=Strict` cookie and its CSP has no
  `script-src 'unsafe-inline'`.** The panel loads its script from a file for exactly that reason.
- **A whole-token match blocks regardless of the dictionary.** Spellcheck dictionaries contain
  profanity too, so "is it a word" alone would allow everything; `token != match` is what makes the
  containing-word rule correct rather than a no-op.
- **A glued window must match a term exactly.** `f u c k` reassembles into precisely the term;
  `an ass` reassembles into `anass`, which is not a word, so the dictionary would not have saved it.
  Requiring the whole window is what makes separator matching safe.
- **`filter_block.context` is nulled after 30 days**, and the row survives. The privacy notice says
  the text is kept only for the review window; the counts are what tune the lists.
- **Only `severe` is ever global.** A word innocuous in one language is profane in another, so
  `profanity` and `watch` see the comment's own detected language plus English, never a union.
- **`comment.lang` is detected from the text, not taken from the client's locale.** A French-locale
  user writing English would otherwise get the French list and skip the English one, which is both a
  false-positive source and a trivial bypass.
